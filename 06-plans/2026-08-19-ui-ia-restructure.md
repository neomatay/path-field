# UI 信息架构重构：画报风格 + 仪表盘结构

> 归档自 Claude Code 会话 plan 文件（原 stateless-baking-barto.md，2026-08-19）。
> 已实施于 commit 28718a7（"UI 信息架构重构：画报仪表盘"），验证与部署随该提交完成。

## Context

用户反馈（对标 sigma.run）：现在的界面是"内容的罗列，字太多，看不到重点，也没有分类"。诊断：问题不在配色和字体（画报视觉保留），而在信息架构——每屏是十几节裸 section 线性堆叠，说明文字和操作混在一起，没有视觉焦点，没有分组导航。

已确认的方向：
- **画报风格 + 仪表盘结构**：纸面/墨绿/日晒黄、路线地图、印刷排版保留，信息架构彻底重构
- **一键开始，签到可选**：开始训练不再被签到问题拦路，签到变成可选微调

重构三原则：
1. **每屏一个主焦点**——大数字或大按钮，其他全部退后
2. **模块分组**——相关信息收进带标题的折叠块（native `<details>`），默认只露出标题行
3. **文字标签化**——句子退化为「标签 + 数值」，每屏正文句子最多一句

## 各屏重构设计

### 今天页（主焦点 = 开始按钮）
```
今天的训练 · 全身 A
┌──────────────────────┐
│      开始训练          │   <- 全屏最大主按钮（primary 放大版）
│  完整版约 50 分钟       │
└──────────────────────┘
本周 1/2 次 · 周连击 3        <- 数字条（一行 stat）
▸ 状态微调（可选）            <- 折叠：时间/精力/睡眠/不适 chips
▸ 今天练什么                  <- 折叠：动作清单
```
- 删除：Mission 大标题区（信息在旅程页）、最近记录列表（记录 tab 有）
- 签到逻辑：未答任何签到 → 默认完整版直接开练；答了 → 规则引擎实时改按钮上的推荐版本与时长（睡眠<6h→短版按钮、不适→恢复）。红旗信号仍然禁止完整版（安全底线不动）
- 体重轻提示并入数字条右侧一个"记体重"小链接

### 旅程页（主焦点 = 路线地图）
```
[ParkArt 路线地图]            <- 产品身份，置顶放大
已点亮 3/8 · 距下个营地 1 次 · 周连击 3
[成就印章带]
▸ 计划详情                    <- 折叠：每周节奏 + 每节课动作
▸ Mission 与规则              <- 折叠：成功证据 / 不作为裁判 / 进阶 / 安全边界 / 注意部位
```
- 地图下方的一行数字合并原来三个 section（streak-row、route-status、mission-stamp 标题区）
- 所有长文（成功证据列表、三版本说明、规则）全部进折叠，默认收起

### 记录页（页内分类 tab）
```
12 次训练 · 容量趋势 +8%
[训练] [身体] [最佳]           <- 页内 sub-tabs
```
- **训练**：统计带 + 记录卡片（现状保留，去掉空态长文案）
- **身体**：录入表单 + 体重趋势线 + 最近数据（从底部小节升级为独立 tab）
- **最佳**：关键动作 PR 列表（从统计带下方独立成 tab）

### 收据页 / 训练页 / 入口
- 收据页已是数字摘要结构，微调：动作清单保留，收尾
- 训练页逐动作卡片结构合理，不动
- 入口（路径卡 + 三快问 + 预览）结构合理，不动

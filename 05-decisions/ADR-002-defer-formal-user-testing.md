# ADR-002: 推迟正式用户测试，v0.2 以创始人自用验证

## 决定

**不执行** ADR-001 定义的 8-12 人正式原型测试，改为：

1. 先基于现有原型实现 v0.2 可实际使用的本地优先 PWA（范围见 [ROADMAP_v0_2.md](../ROADMAP_v0_2.md)）；
2. v0.2 完成后，由创始人（本人）在真实训练中连续使用 2-4 周，在实践使用中发现问题、调整方向；
3. 正式用户测试**推迟而非取消**：在 v0.3（账户、云同步、多用户试用）启动前，复用现有 [V1_PROTOTYPE_VALIDATION.md](../V1_PROTOTYPE_VALIDATION.md) 与 [测试执行包](../04-task-playbooks/USER_TEST_EXECUTION_PACK_V0_1.md) 对可运行产品做一轮轻量测试（3-5 人即可），并按当时的产品形态修订脚本。

## 背景

- 这是一个个人项目，没有团队、研究预算和现成用户渠道；问卷式调研无法验证"训练现场好不好用、建议能不能被理解"这类核心问题。
- 现有验证方案（35 分钟任务式测试、招募配额、评分表）为正式研究设计，在当前阶段执行成本高于其信息价值。
- 创始人本人是典型目标用户（有规律训练、平台期焦虑、在多个工具间切换、有中断经历），具备"自用即验证"的条件。
- 产品当前处于原型阶段，最大的未知不是"用户怎么说"，而是"闭环在真实使用中是否成立"——这只能用真实产品回答。

## 自用验证的通过标准

连续 2-4 周真实使用后，满足以下全部条件，v0.2 判为通过：

1. 完整记录 **>= 8 次真实训练**（含至少 1 次短版或恢复版的选择）；
2. 完成 **>= 2 次周复盘**，且至少 1 次据此确认或修改了下一步计划；
3. 至少经历或模拟 1 次中断重返流程（不清零、不补债的表达经受住真实情绪检验）；
4. 全程**没有退回训记**记录训练；
5. 主观判断：它对"我今天的训练是否有效、接下来怎么练"的回答，比之前的工具组合（训记 + 薄荷 + iWatch）更清楚、更省心。

任何一条不满足，先修 v0.2 再谈 v0.3。

## 因推迟测试而仍未验证的假设

以下假设在 v0.2 阶段**只能由创始人单方验证或不验证**，在向他人推广前必须重新检验：

| 假设 | 自用能否验证 | 风险 |
|---|---|---|
| Mission 对普通用户可理解、可复述 | 部分（作者是产品方，理解力不代表用户） | 高 |
| 短版/恢复/暂停不被读成失败或惩罚 | 部分（作者认可该理念，存在确认偏差） | 高 |
| fact/observation/toConfirm 四层分类对新手不是认知负担 | 否 | 高 |
| 重返表达在真实中断情绪下不引发羞耻 | 是（作者有真实中断经历） | 中 |
| 安全分流被理解为"停止高强度"而非"产品在诊断我" | 部分 | 中 |
| 阶段海报可分享且不失真 | 部分 | 低 |

## 记录与调整纪律

自用期间的发现统一记入 `SELF_USE_FINDINGS.md`（随 v0.2 开发创建），并区分两类：

- **问题类**（bug、不好用、缺功能）：随手修，不改变方向；
- **方向类**（连作者都觉得 Mission 啰嗦、四层证据嫌烦、路线可视化无感）：只记录，攒 2-3 周后统一判断，不因单次体验改方向。

## 影响

- ADR-001 的"验证闸门"（8-12 人原型测试后再进生产开发）由本决定取代；其人群收窄、P0 边界、安全规则继续有效。
- [V1_PROTOTYPE_VALIDATION.md](../V1_PROTOTYPE_VALIDATION.md) 与 [测试执行包](../04-task-playbooks/USER_TEST_EXECUTION_PACK_V0_1.md) 标记为 `deferred`：保留复用，不再是 v0.2 的前置条件。
- v0.2 起所有产品表述不得使用"已被用户验证"；对外展示前须完成推迟的轻量测试。
- 后端、账户、多用户（v0.3）在本决定的自用验证通过前不启动。

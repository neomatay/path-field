## 一、产品概述

### 1.1 产品定位

FitJourney 不是一个冷冰冰的健身记录工具，而是一个有温度的 AI 健身陪伴伙伴。它不仅帮助用户制定训练计划、记录运动数据，更核心的是它能"懂你"——根据用户的每日状态动态调整计划，用游戏化的方式让用户愿意坚持，用智能数据分析让用户看到进步。

本质上是把"私人教练 + 游戏化激励 + 智能分析"融合在一个 App 中。

### 1.2 目标用户画像

产品面向三类用户，对应不同的运动基础分层：

- **运动小白**：缺乏训练知识，不知道从何开始，容易半途而废。需要"被牵着走"的体验，计划要极简，反馈要及时，激励要频繁。
- **有点基础**：有健身经验但训练计划不系统，容易遇到瓶颈。需要"被点拨"的体验，期待更科学的周期安排和瓶颈突破建议。
- **熟练工**：有自主训练能力，追求精细化数据分析和周期化管理。需要"被挑战"的体验，关注数据深度、动作进阶和长期趋势。

### 1.3 核心价值主张

- **极简上手**：3-5 个问题即可生成首版个性化训练计划
- **动态调整**：每日根据状态反馈实时微调当天训练内容
- **全程陪伴**：从计划制定到训练打卡到数据分析，全程有 AI 教练陪伴
- **游戏化激励**：闯关、地图解锁、成就系统，让坚持训练变得有趣
- **智能洞察**：不只是报数据，而是给出有诊断价值的教练建议

## 二、核心功能详述

### 2.1 智能训练计划生成与动态调整

#### 2.1.1 极简 Onboarding 流程

用户首次使用 App，只需回答 3-5 个问题即可生成首版训练计划：

| 序号 | 问题 | 选项示例 | 影响维度 |
|---|---|---|---|
| 1 | 你的运动基础？ | 小白 / 有点基础 / 熟练工 | 决定计划复杂度和动作难度 |
| 2 | 你的主要目标？ | 减脂 / 增肌 / 塑形 / 提升体能 / 康复矫正 | 决定训练侧重方向 |
| 3 | 每周能练几天？每次多久？ | 2-3天/30min, 3-4天/45min, 5+天/60min | 决定计划容量 |
| 4 | 有伤病或需注意的部位吗？ | 无 / 膝盖 / 腰椎 / 肩膀 / 其他 | 决定动作禁忌 |
| 5 | 偏好训练方式？ | 器械 / 自重 / 混合 / 户外 | 决定动作库范围 |

问题以卡片式逐个展示，支持滑动选择，整体耗时控制在 30 秒以内。

#### 2.1.2 计划分层结构

训练计划采用三层周期化结构：

- **宏周期（Macro Cycle）**：8-12 周为一个阶段，例如"基础适应期 → 力量增长期 → 塑形冲刺期"。每个宏周期有明确的目标和评估标准。
- **中周期（Meso Cycle）**：每 2-4 周为一个模块，逐步增加强度或变换训练重点。中周期结束时自动触发计划适配性评估。
- **微周期（Micro Cycle）**：每周的训练安排，精确到每天练什么。微周期内支持根据每日状态灵活调整。

这样既有长期方向感，又有短期灵活度，用户随时知道自己处于什么阶段、下一步要去哪里。

#### 2.1.3 每日动态调整机制

每天训练前（或当天早晨），App 弹出极简的"今日状态签到"：

- 昨晚睡了多久？（滑块选择，4-10 小时）
- 今天身体感觉如何？（1-5 分，可展开身体部位热力图标记不适区域）
- 昨天训练后肌肉酸痛程度？（1-5 分）
- 今天心情怎么样？（emoji 选择）
- 今天有多少时间可以练？（15min / 30min / 45min / 60min / 90min）

AI 根据这些输入在几秒内微调当天计划：

- 状态差 → 降低训练容量（组数/次数减少 20-30%）或切换为主动恢复日
- 状态好 → 适度加重（重量上浮 5-10%）或增加一组
- 时间不够 → 浓缩为核心动作，去掉辅助动作
- 酸痛严重 → 避开相关肌群，调整训练部位

#### 2.1.4 动作库与计划模板

系统内置分级动作库，每个动作包含：

- 动作名称和分类（力量/有氧/柔韧性/核心）
- 难度等级（1-5 星）
- 目标肌群
- 动作示范（视频或 3D 动画）
- 退阶和进阶变体
- 常见错误提示
- 适合的运动基础等级

计划模板按"目标 × 基础等级 × 频率"组合预生成，AI 在模板基础上根据用户个性化信息做针对性调整。

### 2.2 训练记录与数据采集

#### 2.2.1 训练打卡机制

- **训练模式**：用户点击"开始训练"后进入沉浸式训练模式，逐个动作展示，支持查看动作示范视频。每个动作完成后记录：
  - 完成组数
  - 每组次数
  - 每组重量（如有）
  - RPE（主观疲劳度，1-10 分滑块）
- **训练总结**：训练结束后自动生成训练摘要：
  - 总训练时长
  - 总完成组数
  - 总训练容量（组数 × 次数 × 重量）
  - 平均 RPE
  - 与上次同类训练的对比（容量变化百分比）
- **快速打卡模式**：适用于跑步、骑行等有氧运动，只记录开始/结束时间和运动类型，适合不想精细记录的用户。

#### 2.2.2 身体数据定期采集

系统设置定期采集节点，以渐进方式收集身体数据：

| 周期 | 采集内容 | 方式 |
|---|---|---|
| 每周 | 体重、主观体感评分 | 滑块输入 |
| 每两周 | 围度数据（腰围、臀围、大腿围等） | 手动输入 + 拍照对比 |
| 每月 | 体脂率（如有体脂秤）、体能基准测试 | 手动输入 / 引导测试 |
| 按需 | 异常状态记录（如某天膝盖不舒服） | 自由文本 + 部位标记 |

体能基准测试项目根据用户目标定制，例如：最大俯卧撑次数、1km 跑时间、平板支撑时长、深蹲 1RM 估算等。每次测试结果自动记录为 PR（个人记录）。

#### 2.2.3 可穿戴设备数据接入

接入优先级：

- 第一批：Apple Watch（HealthKit）、华为运动健康
- 第二批：小米手环、Garmin
- 第三批：Oppo、其他安卓厂商

核心采集数据：

- 实时心率及心率区间分布
- 卡路里消耗估算
- 运动轨迹（户外运动）
- 高阶数据：HRV（心率变异性）用于恢复状态评估、睡眠数据用于疲劳管理

设计原则：不强制要求佩戴手表。没有手表的用户通过 RPE 等主观指标同样可以完整使用所有功能，只是分析维度相对较少。有手表的用户自动获得更丰富的数据洞察。

### 2.3 智能分析与教练建议

产品的核心差异化能力——AI 不只是报数据，而是要"说出有洞察的话"。

#### 2.3.1 进步分析

- **训练容量趋势**：对比 4 周前和现在的总训练容量、关键动作的重量变化，用图表直观展示进步幅度。例如"你的深蹲重量比一个月前提升了 10%，太棒了！"
- **体能基准追踪**：每次基准测试结果自动对比历史，标记 PR 突破，展示进步曲线。
- **身体数据变化**：体重/围度/体脂的趋势线，标注关键节点和变化幅度，区分"好变化"和"需关注的变化"。

#### 2.3.2 状态诊断

系统持续监控训练数据模式，检测到异常时主动给出诊断：

| 触发条件 | 诊断建议示例 |
|---|---|
| 连续 3 天 RPE 偏高 + 睡眠不足 | "你最近训练强度偏高但恢复不足，建议明天安排主动恢复日" |
| 训练容量连续 2 周下降 | "训练表现有下滑趋势，可能原因：睡眠质量下降 / 训练频率过高 / 蛋白质摄入不足，建议..." |
| 静息心率连续升高 | "静息心率持续升高可能提示过度训练，建议适当降低本周训练容量 30%" |
| 连续 5 天未训练 | "最近几天没看到你训练，一切都好吗？如果需要调整计划随时告诉我" |

诊断语气要像一个真正关心用户的教练，而不是冷冰冰的系统通知。

#### 2.3.3 计划适配性评估

每 2-4 周自动生成一次"计划体检报告"，包含：

- 当前计划是否还匹配用户目标
- 训练频率执行率如何，是否需要调整计划天数
- 哪些动作已经可以升级（加重或换进阶变体）
- 哪些动作需要退阶或替换
- 是否到了该切换中周期的时机
- 下一步调整方向建议

#### 2.3.4 下一步建议

基于以上分析，给出具体可执行的调整建议：

- 下周计划微调方案（具体到哪天改什么）
- 新动作推荐及理由
- 恢复策略建议（拉伸/按摩/睡眠/营养）
- 目标调整建议（如发现当前目标不合理）

建议以"教练对话"形式呈现，用户可以直接回复"采纳"或"调整一下"，AI 据此更新计划。

### 2.4 游戏化闯关系统

#### 2.4.1 关卡系统

- 每天的训练即为一关，完成训练即可通关
- 关卡有难度星级（根据当天训练强度），完成高难度关卡获得更多奖励
- 周末设有"Boss 关"（本周最难的训练日），通关有额外奖励

连击机制：

| 连击天数 | 里程碑名称 | 奖励 |
|---|---|---|
| 1 | 起步 | 训练币 ×10 |
| 7 | 小试牛刀 | 徽章 + 训练币 ×50 |
| 14 | 渐入佳境 | 地图解锁 + 训练币 ×100 |
| 30 | 坚持之星 | 限定皮肤 + 训练币 ×300 |
| 100 | 百日传奇 | 传奇徽章 + 训练币 ×1000 |

连击中断时提供"复活卡"机制（每月 1 张），使用后保持连击不中断。

#### 2.4.2 地图解锁

设计虚拟的"健身世界地图"，用户通过持续训练逐步探索：

| 解锁条件 | 地图名称 | 视觉风格 |
|---|---|---|
| 初始解锁 | 新手村 | 清新草地 |
| 累计训练 7 天 | 力量森林 | 热带丛林 |
| 累计训练 21 天 | 耐力高原 | 雪山高原 |
| 累计训练 50 天 | 塑形海岸 | 阳光海滩 |
| 累计训练 100 天 | 传奇竞技场 | 古罗马竞技场 |

地图上设有里程碑节点，到达后有特殊奖励。同时设计季节性限定地图（夏季海滩地图、冬季雪山地图），增加新鲜感。

#### 2.4.3 奖励系统

- **训练币**：每次完成训练获得，数量与训练难度和时长相关。可用于：
  - 兑换虚拟装备（给虚拟角色换装）
  - 兑换真实优惠（运动品牌折扣券等）
  - 解锁特殊训练计划模板
- **成就徽章**：设计 100+ 个成就，持续给用户追求感。示例：
  - 里程碑类：首次完成训练、累计 50 小时、累计 100 小时
  - 连击类：7天连击、30天连击、100天连击
  - 力量类：第一次 PR、深蹲破百、卧推破百
  - 坚持类：第一次主动恢复日、连续 4 周完成全部计划
  - 特殊类：雨中训练、凌晨 6 点前训练、深夜 10 点后训练
- **等级系统**：根据累计训练量和坚持天数综合计算等级，不同等级解锁不同功能：
  - Lv1-5：基础功能和计划模板
  - Lv6-15：高级训练计划模板、更详细数据分析
  - Lv16+：自定义计划编辑、社区计划分享权限

#### 2.4.4 社交与竞争（二期）

- 好友系统：看到朋友的训练动态，互相点赞加油
- 每周挑战：和好友比拼本周训练时长/容量
- 排行榜：分好友圈和全局，按周/月排名

## 三、补充功能模块

### 3.1 饮食记录（轻量版）

健身效果三分练七分吃，设计极简饮食打卡功能，不过度增加用户负担：

- 每天选择"饮食自律程度"（1-5 分）
- 可选拍一张三餐照片，AI 给出粗略评价
- 不要求精确记录每卡路里，但能将饮食因素纳入训练效果分析维度

### 3.2 休息与恢复管理

恢复也是训练的一部分：

- 每周强制安排 1-2 个休息日，休息日也有"通关"内容（拉伸/冥想/散步等主动恢复）
- 睡眠数据接入后，AI 根据睡眠质量调整第二天训练强度
- HRV 数据评估恢复状态（如有设备），给出恢复建议

### 3.3 社区内容（轻量版）

- 每日推送一条健身小知识，配合当天训练内容
- 用户可分享训练成就到社区
- 优质训练计划可社区共享（熟练工创建的计划供小白参考）

### 3.4 声音陪伴体验

- 训练时可选语音教练，在动作间隙给出鼓励
- 训练结束后语音总结当日表现
- 语音风格可选：温柔鼓励型 / 严格教练型 / 活力伙伴型

## 四、产品节奏与迭代规划

### 4.1 MVP 阶段（V1.0）

聚焦核心闭环：计划生成 → 每日打卡 → 基础分析

- 极简 Onboarding + 计划生成
- 每日训练打卡 + 状态签到 + 动态调整
- 基础进步分析（容量趋势、PR 记录）
- 游戏化简版（打卡 + 连击 + 基础成就）
- 身体数据定期采集

### 4.2 二期（V2.0）

扩展深度与广度：

- 可穿戴设备数据接入（Apple Watch 优先）
- 完整游戏化系统（地图解锁、等级系统、训练币商城）
- 智能诊断与计划适配性评估
- 饮食记录轻量版
- 声音陪伴体验

### 4.3 三期（V3.0）

社交化与智能化升级：

- 社交功能（好友、挑战、排行榜）
- 社区内容与计划分享
- 大模型驱动的教练对话系统
- 更多设备接入（Garmin、小米等）
- 季节性限定活动

## 五、技术方案要点

### 5.1 AI 计划调整实现路径

- **前期（MVP）**：规则引擎 + 模板组合。维护一套动作库和计划模板，根据用户输入做条件分支调整。优势是响应快、可控性强。
- **后期（V2+）**：引入大语言模型做更智能的个性化调整和教练式对话。规则引擎保证安全底线（如伤病禁忌），大模型负责自然语言交互和个性化建议生成。

### 5.2 数据架构要点

- 用户数据：基础信息、训练偏好、伤病记录
- 计划数据：宏/中/微周期结构、每日训练内容
- 训练记录：每次训练的详细数据（组数、次数、重量、RPE）
- 身体数据：体重、围度、体脂、体能测试结果的时间序列
- 设备数据：心率、睡眠、HRV 等（二期接入）
- 游戏数据：连击、成就、等级、训练币记录

### 5.3 平台选择

首选移动端（iOS + Android），可采用 React Native 或 Flutter 跨平台开发。Apple Watch / 安卓手表端通过各自原生 SDK 接入。

## 六、关键设计原则

- **极简优先**：所有交互都在做减法，30 秒完成 Onboarding，5 秒完成状态签到，一键开始训练
- **温度感**：所有文案和提示都采用对话式语气，像一个懂你的朋友，而不是一个冷冰冰的工具
- **渐进式深度**：小白看到的是简单计划，熟练工可以深入到每组数据的分析，同一产品服务不同深度需求
- **正向激励**：更多关注用户做到了什么，而不是没做到什么。失败时不指责，而是温柔地鼓励再来
- **数据驱动但有温度**：用数据支撑建议，但用人类语言表达洞察

## 七、开放讨论项

以下问题需进一步讨论确认：

1. 产品名称是否定为 FitJourney，还是需要重新构思？
2. MVP 的平台选择：先做 iOS 还是 iOS + Android 同步？
3. 动作库来源：自建还是对接第三方？动作示范视频如何制作？
4. 商业模式：免费 + 内购？订阅制？还是广告？
5. 是否需要做 Web 端管理后台（用户数据管理、内容运营等）？
6. 私密性考量：身体数据如何保障隐私，是否需要做端到端加密？
